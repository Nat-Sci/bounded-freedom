# Task record: local usage audit and routing hardening

## Intent

- Objective: Convert an anonymous local Codex usage audit into bounded orchestration, lifecycle, timeout, checkpoint, routing-evaluation, task-record, and scientific data-quality improvements.
- Non-goals: Infer billing from unreliable token fields, preserve message or command content, edit Codex state databases, create a standing worker crew, add a statistical-inference Skill, or implement a complete scientific pipeline.
- Assumptions and uncertainty: Local state tables are migration-dependent and do not prove causal effects. Thread counts are not token counts, and an `open` spawn edge does not prove that a worker process is running.

## Chief decision

- Task method: `cost-efficient-orchestration` for routing and lifecycle changes; `skill-creator` for the new and revised Skills.
- Assurance: S1. This changes execution and scientific data-quality contracts but does not inspect project data, change numerical results, or make a scientific claim.
- Execution contract: Direct Chief work. One owner keeps the privacy, routing, documentation, and installation boundaries consistent.
- Model and capability lane: Current Chief with strong reasoning for contract synthesis; no delegated model route.
- Planned workers: 0 distinct workers and 0 spawn attempts.
- Actual workers: 0 distinct workers, 0 spawn attempts, and no worker lifecycle leftovers.
- Worker-budget rationale: The affected files are already known, and delegation would duplicate context or add privacy-sensitive handoff cost.
- Owned scope: Orchestration Skill and focused references, task template, routing documentation, one repository data-quality Skill, one personal aggregate-only audit Skill, installer-visible Skill inventory, and the current audit visualization.
- Verification: Validate every Skill, run deterministic audit-script tests, run installer regression tests and dry-run discovery, check links and whitespace, inspect the diff, and scan changed or generated text for private machine identifiers.
- Stop conditions: No raw titles, messages, commands, working directories, remote addresses, or token-cost claims; no direct state-database mutation; no automatic statistical inference, exclusion, or full-pipeline implementation.

## Decision

- Outcome: Accepted for publication. The repository contract and documentation are coherent, the new scientific method remains bounded, the personal audit is read-only and aggregate-only, all supported adapters are deployed, and the current task has zero live child workers. Historical stored `open` edges were not edited or misrepresented as live processes.
- Alternatives rejected: Direct SQLite cleanup, token-derived cost estimates, a task-wide model profile, and a broad scientific-analysis Skill.
- Remaining uncertainty: Real model cost-quality differences require repeated representative Builder tasks and independent acceptance checks. Routing prompts still need longitudinal calibration in fresh sessions, and historical lifecycle edges can only be reconciled safely when a supported host control confirms the corresponding worker is complete.
