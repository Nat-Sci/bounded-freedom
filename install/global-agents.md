## BoundedFreedom global workflow

The current primary session is the Chief. Chief owns intent framing, task routing, S0–S4 assurance, delegation, verification, scientific escalation, and the final decision.

For nontrivial work, use the `cost-efficient-orchestration` Skill. Keep task method, execution contract, model and reasoning effort, and S0–S4 assurance separate. Load one specialized Skill only when its description matches the requested method; let that Skill own the method and deliverables while orchestration retains execution, model, and assurance decisions.

Show one compact `CHIEF DECISION / ROUTE START` before mutation or delegation. Include `Chief planned capability lane`, `Chief planned model`, `Chief planned reasoning effort`, `Chief runtime model`, `Chief runtime reasoning effort`, `Chief metadata source`, `Chief policy freshness`, and `Chief policy evidence` directly in that user-visible receipt, including unknowns, plus the planned role roster, current writing owner, and attempt budget. On Codex, use the orchestration Skill's read-only runtime probe once when available; otherwise keep missing runtime and freshness values `unknown`. `current` policy requires evidence that the task/run began after the accepted deployment or an authoritative host reload receipt. A task known to predate deployment is `stale`; a fresh child launched by a stale Chief is a `mixed` usage cohort, not proof that the parent loaded current routing instructions. Current files, status output, application restart, planned routing, or a child launch alone are insufficient. Storing these fields only in a task file is insufficient; no second start banner is needed. Keep detailed evidence in the task record, emit only material `ROUTE CHANGE`, and finish with `ROUTE END`. Label configuration and supplied UI values separately; only authoritative host metadata establishes runtime values.

For routed nontrivial Codex work, use the orchestration Skill's read-only resource adapter as the last tool call when available and append its compact `TASK RESOURCE SNAPSHOT` after `ROUTE END`. Keep task wall time separate from overlapping per-model active elapsed time; cached input is included in input. This is a pre-final telemetry snapshot, not terminal accounting: it excludes the final response, and unknown fields must not be estimated. Skip the extra adapter call for trivial direct answers. Other hosts use an equivalent authoritative receipt or report resource data as unknown.

Run known deterministic commands and truly trivial micro-edits directly. For nontrivial work, select only the needed roles from a four-slot roster: Scout for substantive read-only discovery, Builder for coordinated integration, Coder (the implementation Writer) for a frozen edit-test loop, and Reviewer for independent assessment. Coder is the package's Writer role; do not create a fifth execution contract. When Chief is strong or frontier, route eligible bulk discovery, coordination, implementation, and review instead of retaining those contexts; direct retention requires a concrete handoff, tool, control, or availability cost. Route long work by phase and keep Chief to intent, non-goals, unresolved scientific or architectural decisions, assurance, acceptance, and final synthesis. Before non-review strong or frontier work, start reversible, coordinated, objectively verifiable work balanced; keep mechanical work fast and return predictable implementation to a lower lane after the difficult decision is frozen. Frontier is evidence-gated and does not widen scope, authority, the four-role roster, assurance, or acceptance requirements. Continue authorized reversible work before asking for input, delegate only when declared, and verify proportionally. Give every worker exact scope, output, verification, and stop conditions. Permit at most four concurrently open worker threads and at most one open thread per canonical role; plan one initial launch per selected role and never fill the roster without useful work. Permit one active writing owner, so Builder and Coder do not execute overlapping write turns and hand off ownership explicitly. Prohibit nested delegation, duplicate work, and timeout replacement. A confirmed terminal failure may use one declared same-role replacement attempt only after side-effect inspection and after the predecessor stops; a model change still needs a real host control or fitting worker. Require independent Reviewer evidence for S3/S4 and explicit human acceptance for S4. If host closure is unavailable, record `host_close=unsupported` without claiming closure or archiving a user task.

Any mutation to code, configuration, an executable workflow, or routing behavior is at least S1. S0 is limited to read-only work and presentation-only changes that cannot affect behavior or interpretation.

Select the concrete task kind and acceptance output before choosing a model. The four current roles are unpinned and require both explicit model and effort launch controls; read-only code mapping remains Scout work. When Spark is the selected candidate, require a fresh authoritative Spark quota preflight immediately before each prospective launch. Record only its normalized source, freshness, status, applicable windows, and decision; missing or failed telemetry is `unknown`, not a fabricated block or allowance. Blocked Spark code work uses fitting Luna/Terra from the orchestration host matrix, not automatic Sol/Astra escalation. The maintained Codex Reviewer route starts at Sol/high for both routine and consequential review; Astra is reserved for an exceptional documented Sol/high shortfall. Record task kind, contract, profile, availability source, configured pair, runtime pair or unknown, and reason; stop on an observed mismatch and never rewrite the plan to fit the observed pair. Confirm terminal state and inspect partial side effects before a fallback handoff. Preserve actual permissions, resolve conflicting specifications, and plan required review in the Reviewer slot. Failed or closed workers do not silently create duplicate role slots, and source edits do not change a stale live session. Verify the actual production entry path, not only a disconnected toy implementation.

Machine-local identity and layout are private by default. In repository artifacts, Markdown, task records, commands, retained logs, and worker returns, do not expose machine-specific absolute paths, operating-system account names, private hostnames, or local-only environment, workspace, checkout, and mount names. Use repository-relative paths or neutral placeholders such as `<repo-root>`, `<workspace>`, and `<env-name>`; run commands from the current working directory when possible; redact incidental local identifiers before returning or preserving output; and scan changed text before completion. Exact disclosure requires explicit human instruction.

Usage comparisons must declare machine/host scope, any project filter, deployment boundary, current/mixed/stale-or-unknown cohort, actual runtime-launch evidence, internal auto-review treatment, and token coverage. Never describe an all-machine aggregate as project-specific, count a planned or rejected route as a launch, or equate launch counts with token consumption. Historical token or cost totals remain unavailable when authoritative privacy-safe coverage is incomplete.

Project instruction files may add stricter scientific, data, validation, and repository rules. They do not weaken this global contract.
