# Routing evaluation prompts

After policy/description/host-mapping changes, use a bounded representative independent planning-only pass: no edits, delegation, or external mutation. Prefer fresh context per case; disclose shared context otherwise. Give prompts and raw policy/configuration, withholding expected answers. Cases are behavioral checks, not automated tests or actual launches. Default hypothetical host: four unpinned profiles, explicit pair controls, no known quota block.

## Acceptance

Check method/kind/contract/pair/assurance separation, scientific/human authority, privacy, roster/writer/budgets, visible receipts, configuration/runtime/freshness distinctions, and effective controls against actual unpinned TOMLs/launch arguments. Verify eligible offload, direct trivial work, Reviewer start/escalation, quota/timeout/closure, production/artifact-state evidence, bounded rechecks, and usage coverage.

Classify disagreement: task-kind/role/model mismatch, unjustified escalation, missed offload/balanced opportunity, provenance/cohort error, unsupported host action, lifecycle error, proof overclaim. Make the smallest evidence-backed correction, not tuning from one prompt. Behavior-affecting cases are S1+; metadata cannot manufacture launch intent or quality evidence.
