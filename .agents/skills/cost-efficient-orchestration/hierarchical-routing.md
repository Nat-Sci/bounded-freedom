# Hierarchical routing and calibration

Read for substantial implementation/delegation, multi-phase or strong/frontier work, or optional calibration; no standing hierarchy is required.

## Phase control

`admission -> bounded method -> execution/lane -> verification -> checkpoint -> next phase or stop`

Chief retains objective meaning, non-goals, decision constraints, unresolved science/architecture, assurance, acceptance, lifecycle, and final synthesis. Scout supplies facts; Builder decomposes an accepted goal into interfaces, dependencies, bounded packets, and checks without redefining it.

Each phase carries frozen objective/permissions, active rules, bounded files/evidence, observables/checks, and return boundary. Choose task kind then pair from the [canonical matrix](host-model-routing.md#canonical-task-kind-matrix), not the initial role's pair. Use deterministic inventory/comparison before judgment. Checkpoint material decisions, methods, lanes, and returns; preserve accepted inputs, artifacts, evidence, uncertainty, next action. [Seal milestones](operations-and-lifecycle.md#milestone-consolidation) before expansion.

Choose the least costly adequate available lane: fast mechanical/repeated work; balanced ordinary reasoning/coordinated units; strong justified interacting constraints/review; frontier exceptional coherence or documented lower-lane shortfall. Quota blocks remove options without proving reasoning shortfall. Escalate on observable difficulty and return stable work down. Frontier must produce a frozen decision/interface/evidence boundary/implementation contract, not absorb routine edits/testing.

Select an early minimal check through the actual production entry point. Toy-engine, scaffold, or helper-only success is not integration evidence. [Operations](operations-and-lifecycle.md) owns roster/ownership/budgets; entry owns receipts.

## Balanced gate and direct work

Before non-review strong or frontier execution, start balanced when work is reversible/bounded, interfaces/evidence stable, acceptance observable, failure detectable before consequential use, and unresolved science/architecture stays with Chief. Keep mechanical volume fast; no model-share target or separate allowance consumption.

Name the actual edit-test-repair owner before substantial implementation. Recommendations/analysis alone are not implementation offload. Strong/frontier Chief freezes and routes predictable objectively verifiable units to fitting Coder (narrow loop) or Builder (coupled integration). Retiring context suffices; concurrent Chief work is unnecessary.

Known commands/genuine micro-edits stay direct. A concrete handoff, tool, control, or availability cost may justify direct implementation for one bounded unit; record it and reassess at the next safe boundary when work expands into sustained implementation/repair. Scope knowledge or phase labels are not exceptions/model changes. A failed command alone does not mandate spawning. Historical missed-offload claims stay conditional without established launch support/handoff cost.

Ordinary repair stays with the fitting writer. Explicit ownership transfer requires artifact/worker-state inspection and [lifecycle controls](operations-and-lifecycle.md#worker-lifecycle). Where workers may author permitted patches and Chief applies them, distinguish author/applicator, preserve sandbox, and never bypass rejected writes or claim protected-source mutation. Apply and production-check the exact authored diff before acceptance.

Returns identify artifacts/version or fingerprint when practical, checks/outcomes, gaps, repair owner. Chief uses targeted artifact/diff inspection and sufficient returned evidence instead of wholesale reproduction. Rechecks are justified by changed source/environment/inputs, inadequate evidence, failure/flakiness, new coverage, or independent review. Poll/report reads are not reruns; identical commands alone do not prove duplication.

Final review/acceptance binds one coherent artifact state and checks. Review during editing is advisory. Changes reopen affected conclusions/checks/review only; preserve unaffected evidence and independent Reviewer/S3–S4 gates.

Chief is not an overflow worker: substantive mapping/log reading, coordination, implementation/test loops, and independent review leave Chief when fitting roles/controls exist. After returns/material changes retain accepted evidence, current artifacts, unresolved choices, verification, next action; reopen full worker context only for concrete evidence gaps.

## Calibration

Optional bounded calibration uses actual accepted work: balanced-eligible starts, first-pass acceptance, evidence coverage, rework/retries/escalation, elapsed time, authoritative billed cost/quota or unknown. Promote only evidence-preserving routes improving expected cost per accepted unit. No compulsory extra work, model shares, quota consumption, inferred billing, or causal claims from counts/tokens.
